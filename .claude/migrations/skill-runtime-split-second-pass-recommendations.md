# Skill Runtime Split — 二次优化建议

日期：2026-05-28
审计范围：`.worktrees/skill-runtime-split-design` worktree，Phase 1–5 已实施内容。

---

## 1. Spec/Plan 设计层问题

### 1.1 Phase 5 scope rule 与 phase 4b entry condition 存在隐式依赖

**优先级：P1**
**证据来源：** `docs/superpowers/plans/2026-05-28-skill-runtime-split-phase-5-regression-closeout.md` Task 6 Step 2
**当前问题：** Phase 5 plan 要求在执行 Phase 4b（物理删除 `.ai/**`）前确认"Phase 4a PR 已至少间隔一个 PR 周期"，但在当前单 worktree 内无法通过 CI/PR 方式验证该条件，只能依赖用户书面授权。Plan 没有提供授权格式或可机器检查的替代条件。
**影响：** 如果后续 closeout agent 直接执行 Task 6，可能在没有充分沉淀期的情况下删除旧代码，无法回滚。
**建议修正：** 在 Phase 4 plan 的 Task 10 Step 1 中增加可机器检查的入场条件：用 `git log --oneline --merges origin/main` 确认 Phase 4a 已合入 main 的 merge commit hash；或用 `KATA_SKIP_4B_CYCLE_CHECK=true` 环境变量显式覆盖。

### 1.2 Phase 2B runtime native config 的 frontmatter 白名单扩展缺乏官方证据追踪

**优先级：P1**
**证据来源：** `engine/src/skills/frontmatter-policy.ts`；spec §2.3 与 Phase 1 plan Task 3 的字段限制说明
**当前问题：** Phase 1 plan 明确要求 `when_to_use`、`model`、`effort`、`paths`、`context`、`agent` 等字段必须等官方证据补齐后再扩展白名单，但 Phase 5 已经直接把这些字段加入了 `CLAUDE_SKILL_FRONTMATTER_FIELD_LIST`，而没有在代码注释或 plan 中记录对应的官方文档证据链接或版本。
**影响：** 检查器通过不代表字段在 Claude Code 运行时有效；若某字段被 Claude Code 忽略，skill 行为与预期不符且无告警。
**建议修正：** 在 `engine/src/skills/frontmatter-policy.ts` 的每个字段旁加注释，引用该字段在官方文档中的出处 URL 或 transcript 路径（spec §2.3 已提及 `agent-aaa6c78b3ffe92de9.jsonl`）；未经验证的字段标注 `// unverified: needs official doc link`。

### 1.3 Phase 3B Workflow YAML step metadata 要求与实际 YAML 不一致

**优先级：P2**
**证据来源：** `docs/skills/contracts/workflows/case-edit.yaml`、`case-hotfix.yaml`、`playwright-automation.yaml`；`engine/src/skills/workflow-schema.ts`
**当前问题：** Phase 3 plan Task 6（Phase 3B Carryover）要求每个 step 必须显式声明 `blackboard_inputs`、`blackboard_outputs`、`references`、`failure_modes`、`human_gates`、`verification`，但 Phase 3B 实际生成的 YAML 中部分 step 仅声明了其中 2-3 个字段。如果 `workflow-schema.ts` 的 `validateWorkflow` 不强制检查这些字段的存在性，检查器会静默通过。
**影响：** workflow YAML 作为唯一规范源，但 step metadata 不完整会导致 review 文档无法正确镜像所有约束，也使 blackboard 追踪不完整。
**建议修正：** 在 `validateWorkflow` 中增加 `STEP_METADATA_MISSING` 规则，要求每个 step 必须声明上述所有字段（允许空数组，但字段本身必须存在）；同时补全三个 Phase 3B workflow YAML 的 step metadata。

## 2. 检查器覆盖不足

### 2.1 INDEX.md 的遗留装饰契约内容未被任何检查器覆盖

**优先级：P1**
**证据来源：** `.claude/INDEX.md`、`.agents/INDEX.md`（已在本次审计中修复）；`engine/src/skills/runtime-sync.ts` 的 `DECORATIVE_CONTRACT_PATTERNS`；`engine/src/skills/runtime-detach.ts` 的 `GENERATED_MARKERS`
**当前问题（修复前）：** 两个 INDEX.md 包含 `*-worker@1`、`*-prompt@1`、`下游 agents/prompts/plugins` 等旧装饰契约模式，这些模式在 `runtime-sync.ts` 中的 `DECORATIVE_CONTRACT_PATTERNS` 只扫描 `SKILL.md` 文件，在 `runtime-detach.ts` 的 `GENERATED_MARKERS` 只查 `generated by kata legacy runtime` 等字符串，两个检查器都不覆盖 INDEX.md 的这类内容。
**影响：** 装饰契约残留可以在 INDEX.md 中无限期存在而不被任何自动检查发现。
**建议修正：** 在 `runtime-detach.ts` 的 `collectRuntimeTextFiles` 扫描 INDEX.md 时，同时检查 `DECORATIVE_CONTRACT_PATTERNS` 中的 `-worker@1` 和 `-prompt@1` 模式（或扩展 `RETIRED_SOURCE_REFERENCES` 包含这些模式）；或在 `runtime-sync.ts` 中增加对 INDEX.md 的扫描。

### 2.2 Codex `agents/openai.yaml` 的 `policy.allow_implicit_invocation` 字段仅检查布尔值，未检查字段完整性

**优先级：P2**
**证据来源：** `engine/src/skills/runtime-sync.ts` 中 `checkCodexOpenAiConfig` 函数
**当前问题：** 检查器要求 `policy.allow_implicit_invocation` 是布尔值，但未检查 `policy` 对象本身是否存在，也未检查 YAML 中是否有其他 Codex 期望的字段（如 `default_prompt`、`tools`）格式正确。
**影响：** 如果 `agents/openai.yaml` 文件存在但内容为空或只有 comments，检查器可能静默通过。
**建议修正：** 在 `checkCodexOpenAiConfig` 中增加对 `policy` 对象存在性的检查，并在错误信息中明确说明最小合法结构（参考 Phase 5 plan Task 2 Step 5 中的 minimal valid content）。

### 2.3 Route check 不验证 `should_trigger`/`should_not_trigger` 样例的实际触发行为

**优先级：P2**
**证据来源：** `engine/src/skills/route-check.ts`；spec §8 第三层 route-check 说明
**当前问题：** `route-check.ts` 只检查 YAML 文件结构（字段存在、entry 格式、样例非空），不执行 prompt 样例对模型的实际触发测试。spec §8 明确要求第三层检查用固定 prompt 样例验证应触发/不得触发/需澄清三类场景，这部分至今未实现。
**影响：** route contract 只能保证结构合规，无法保证实际路由行为与合同一致。
**建议修正：** 明确在 route-check 文档中标注"第一版只做结构检查，prompt 触发验证延期到 Phase X"；避免现有 README 或入口文档暗示 route-check 已覆盖语义触发行为。

## 3. 高优先级建议汇总

| 优先级 | 类别 | 建议 |
| --- | --- | --- |
| P0 | 检查器覆盖 | 扩展 `runtime-detach.ts` 或 `runtime-sync.ts`，让 INDEX.md 中的 `-worker@1`/`-prompt@1`/`下游 agents` 模式被自动检测（本次已手动修复，但检查器未覆盖） |
| P1 | Phase 4b 入场条件 | 在 Phase 4 plan Task 10 中增加可机器验证的 PR 周期条件或用户授权格式 |
| P1 | Frontmatter 白名单证据 | 在 `frontmatter-policy.ts` 中为每个 Claude 扩展字段加注官方文档证据链接 |
| P2 | Workflow step metadata 完整性 | `validateWorkflow` 增加 `STEP_METADATA_MISSING` 规则；补全 Phase 3B 三个 YAML 的 step metadata |
| P2 | Codex openai.yaml 字段完整性 | `checkCodexOpenAiConfig` 增加对 `policy` 对象存在性的检查 |
| P2 | Route check 能力边界声明 | 明确在文档中标注 prompt 触发验证未实现，避免隐式声称覆盖语义行为 |
