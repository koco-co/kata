# 测试规范

## 改后即测

代码（含源代码、测试、脚本、配置）只要有改动，**必须**跑一遍相关单元测试。一旦失败，都要查清根因并修复。

### 规则

1. 改动落盘后立刻跑受影响范围的单元测试，优先用最小作用域，例如 `bun test .claude/scripts/_shared/tests/<area>`；拿不准影响面就跑全量。
2. 任何失败（包括改动前就存在的失败）都必须在当前 worktree 内查到根因并修复。不许只标 TODO、`skip`、`it.todo`、注释掉用例，也不许推给后续 PR。
3. 如果某个失败确实超出本次任务能力范围（比如需求未冻结、缺外部依赖），必须先停下来，向用户说清失败的用例、对根因的假设、需要谁来拍板，等用户明确同意后才能跳过。不得自己决定推迟。
4. 所有相关测试都通过后，才能进入「合并回 main 再 push」这一步；合并前再跑一次 `bun test` 做最终确认。
5. 纯文档（`*.md`、`docs/**`）改动可以跳过测试；但如果文档里改了命令、路径或配置示例，要手工验证这些示例确实能跑通。

## 测试命令

- 全量：`bun test`。
- 局部：`bun test .claude/scripts/_shared/tests/<area>`。
- 监听模式：`bun run test:watch`。
- Runtime 契约：`bun run check:skills`。
