# 需求澄清遗漏问题清单

写 PRD 前（需求澄清问答阶段）逐条过一遍本清单。**先判是否适用，再决定是否询问**：

- 纯增删改查、答案能从代码/知识库自查到的、明显不涉及的事项 → **禁止提问**，判 `skipped` 或 `self-resolved`
- 确实需要用户裁决的才判 `asked`，进入逐问确认
- 每条判定结果与理由必须写入 `prd/.process/session.json` 的 `checklist_verdicts`

清单条目格式统一为：**主题词**：具体问题？

| ID | 清单问题 | 适用条件（何时可跳过） | 自查来源 |
|:--|:--|:--|:--|
| CL-001 | **兼容与迁移**：旧数据/旧配置/旧接口兼容？ | 纯新增、无存量数据、无既有任务/配置/旧接口时跳过 | 任务调度、数据初始化、兼容层代码 |
| CL-002 | **边界值与枚举**：字段范围、上限、状态机是否完整？ | PRD/源码已给出完整枚举时跳过 | 源码枚举定义、PRD 字段表 |
| CL-003 | **权限与角色**：哪些角色可操作、数据权限范围？ | 无权限区分（所有角色同权）时跳过 | 权限配置代码、菜单基线 |
| CL-004 | **失败与恢复**：执行失败/超时/部分成功如何处理？ | 单次配置类操作、无异步执行时跳过 | 任务执行与状态流转代码 |
| CL-005 | **并发与幂等**：重复提交/并发执行是否影响？ | 无写入型异步任务、无重复触发路径时跳过 | 提交按钮防重、任务锁逻辑 |
| CL-006 | **依赖影响**：改动影响哪些上下游？ | 无跨模块/跨任务依赖时跳过 | 调用关系、血缘代码 |
| CL-007 | **历史与跨分支回归用例归属**：从历史 CSV、其它客户、其它版本/分支纳入的回归用例，是否与本需求同客户、同版本、同页面基线？ | 不引入历史/跨分支用例时可跳过 | 需求所属客户、feature 目录、目标环境 DOM/知识库、源分支归属 |

## 判定语义

- `skipped`：对照「适用条件」判定不涉及；`reason` 必须写明对应适用条件。
- `self-resolved`：从代码/知识库自查出答案；`answer` 必须写入自查结论，PRD 可引用。
- `asked`：确实需要用户裁决；`question_id` 链接到 session 问题，且该问题必须已回答（「不涉及/范围外」也算回答）。

## 沉淀规则

- 澄清或写用例过程中发现新的反复遗漏，先给出建议并取得用户确认，再追加为 `CL-00n` 条目。
- 追加后必须同步 `cli/lib/prd.ts` 的 `PRD_CHECKLIST_SEED`，保持 CLI 强校验与本文一致。
