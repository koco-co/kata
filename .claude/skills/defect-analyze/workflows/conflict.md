# 冲突裁决

## Steps

1. 还原冲突双方
   - 读取冲突标记上下文；可用时同时读取 base、ours、theirs、相关调用方和测试。
   - 完成条件：双方各自改变了什么、为什么改变以及共同约束均有证据。

2. 形成裁决
   - 判断应保留一方、组合双方还是重写共同实现，并说明会丢失或保留的行为。
   - 完成条件：裁决覆盖双方意图、接口契约、数据影响和验证方法，不仅依据单侧代码。

3. 写报告或执行已授权修复
   - 默认使用 [../templates/conflict-report.md](../templates/conflict-report.md) 写报告。
   - 用户明确要求解决冲突时，按裁决修改文件并保留无关改动。
   - 完成条件：报告写明双方意图和决策依据；若执行修复，目标文件不存在冲突标记且没有未解释的行为丢失。

4. 验证
   - 报告运行 `kata defects lint --report <report.md> --exit-code`；代码修复运行受影响测试和冲突标记扫描。
   - 完成条件：已修改代码时测试通过且目标范围内冲突标记为零。
