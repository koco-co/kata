# 知识规则

查询或更新项目业务知识时，按本文执行。

项目知识写入 `workspace/{project}/_shared/knowledge/**`，项目规则写入 `workspace/{project}/_shared/rules/**`，后者保存这个项目的编写和格式约束。业务事实和实现说明要分仓存放；只有用户明确要求时，才能把实现上下文记成业务知识。

置信度低的更新，写入前先和用户确认。除非用户明确指定了目标项目，否则不要跨项目写入。条目要尽量简洁、有来源支撑，清楚标注它保留的是哪个模块、术语、规则、踩坑还是工作流。

查询时，报告命中的知识条目和它的 SourceRef ID。没有可靠条目命中时，直接说明知识库里没有已确认的匹配，不要凭空编造。
