# Workspace 产物约定

- `workspace/<project>/` 只保存项目输入、编辑中的产物和必要运行记录；框架代码、通用 Schema 与共用脚本不放在项目目录。
- 真实客户项目产物优先存放在独立私有仓库或制品存储。框架仓库只保留脱敏且最小的 fixture。
- 每个 feature 使用一致目录：`inputs/`、`cases/`、`automation/`、`runs/`、`.process/`。不得在根目录随意增加同义目录。
- 生成物必须能从受版本控制的输入重建。体积大、短期或含运行环境信息的文件默认忽略。
- 删除运行数据时，只处理明确属于本次任务、记录在 manifest 中的路径。共享环境数据不得按模糊名称批量清理。
- 产物写入采用临时文件后原子替换。已有最终产物默认先生成差异，不静默覆盖。
- 每次运行写入机器可读 `run.json` 和简短的人类摘要；状态、范围、命令、退出码、计数、产物和未解决项必须一致。
