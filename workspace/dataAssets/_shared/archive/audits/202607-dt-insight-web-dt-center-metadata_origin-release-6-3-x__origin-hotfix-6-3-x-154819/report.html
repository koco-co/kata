b-001 缺少 dataSourceType 时被判定为不受控，行列权限校验 fail-open
major api
位置
service/src/main/java/com/dtstack/metadata/service/datapermission/DataPermissionService.java:1574 · batchQueryPermission() 数据权限/批量行列权限查询
现象
调用批量行列权限接口时若省略 dataSourceType，新增早退条件会把 null 当成“不在支持列表中”，直接返回 control=false，且不会查询数据源、表、权限策略或行列权限。
复现步骤
  1. 向 POST /dmetadata/v1/dataPermission/batchQueryPermission 发送包含有效 dtDataSourceId、dbName、tableName、userId、tenantId 的请求，但省略 dataSourceType。
  2. 控制器 checkParams 仅校验 dtDataSourceId、dbName、tableName，因此请求会进入 DataPermissionService.batchQueryPermission。
  3. DataTableService.APPLY_PERMISSION_DATASOURCE_TYPE 不包含 null，新增条件取反后成立，方法在第 1576-1577 行设置 control=false 并提前返回。
期望
dataSourceType 缺失或无法识别时应在接口层拒绝请求，或按受控状态 fail-closed；只有明确且合法的不支持类型才能返回 control=false。
实际
缺失 dataSourceType 的请求成功进入服务并返回 control=false，语义上将该表标记为不受行列权限管控。
根因
新增条件将“缺失/未知的数据源类型”和“明确不支持权限申请的数据源类型”合并处理，同时入口没有补充 dataSourceType 非空校验。
建议
在 DataPermissionController.checkParams 中增加 dataSourceType 非空校验，并在服务层显式区分 null/未知类型与合法的不支持类型；对缺失或未知类型拒绝请求或保持 control=true，避免权限结果 fail-open。
