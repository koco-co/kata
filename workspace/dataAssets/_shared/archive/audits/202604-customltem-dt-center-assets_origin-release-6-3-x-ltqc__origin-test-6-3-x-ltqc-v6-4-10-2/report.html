现象
批量删除接口的 checkParams() 使用 Checks.nonNull(param.getId(), ...) 校验参数，但 id 是 long 基本类型（永远不为 null），真正需要校验的 ids 列表 (getIds()) 却未被检查。当请求传入空/未传 ids 时校验仍通过，服务层静默返回 false，用户无感知删除失败。

b-004 ValueEnumRangeFunctionServiceImpl 单边配置（仅有取值/仅有枚举）时生成挂起运算符的无效 SQL
major logic
位置
service/src/main/java/com/dtstack/assets/service/valid/function/Impl/ValueEnumRangeFunctionServiceImpl.java:83 · generateValueEnumRangeConditions() 质量校验-取值范围&枚举范围
现象
当用户仅配置取值范围或仅配置枚举范围时，generateValueEnumRangeConditions() 生成形如 ((col>1) AND ) 或 ( AND col IN ('1','2','3')) 的 SQL，其中 AND/OR 运算符缺少另一侧操作数，导致 SQL 执行失败。
复现步骤
  1. 新建一条「取值范围&枚举范围」质量规则（functionId=49）
  2. 仅填写取值范围（如 >1 且 <10），不填写枚举值
  3. 保存规则并触发校验执行
  4. generateValueEnumRangeConditions() 生成无效 SQL，执行时报语法错误
期望
当仅配置取值范围时，应只输出取值范围 SQL；当仅配置枚举范围时，应只输出枚举范围 SQL；当两者都配置时，才用 AND/OR 连接
实际
无论范围是否为空，始终执行 String.format("(%s %s %s)", valueSql, operator, enumSql)，空侧以空字符串替代，导致运算符一侧无有效操作数
根因
buildValueRangeSql 和 buildEnumRangeSql 在入参为 null 时返回空字符串，但 generateValueEnumRangeConditions 的最终格式始终将运算符拼在中间，未判断两侧是否为空
建议
在 return 前增加条件判断：如果 valueSql 为空则直接返回 enumSql，如果 enumSql 为空则直接返回 valueSql，两者非空才拼接 operator
