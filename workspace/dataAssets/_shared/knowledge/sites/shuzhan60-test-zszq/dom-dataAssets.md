## 单表校验规则向导 `#/dq/rule/add`

步骤：**① 监控对象 → ② 监控规则 → ③ 调度属性**。

- ① 监控对象字段：`规则名称` / `选择数据源` / `选择 Schema` / `选择数据表` + `数据预览` 链接。**没有「选择数据库」**；StarRocks 库层字段叫 **Schema**（先选数据源，第二个字段才从「选择数据表」变为「选择 Schema」，再出「选择数据表」）。
- `选择数据源` 是可搜索下拉，选项文案 `<名称>（STAR_ROCKS_3X）`，如 `star33（STAR_ROCKS_3X）`、`star3_1（STAR_ROCKS_3X）`、`star_rocks3（STAR_ROCKS_3X）`。按**名称**搜索（搜 "StarRocks" 无结果，搜 "star" 命中）。
- 底部按钮：取消 / 下一步。

## 监控规则表单（② 监控规则 / 规则详情抽屉）

「监控规则」区有「**添加规则 ▼**」下拉，5 大规则：**完整性校验 / 准确性校验 / 规范性校验 / 唯一性校验 / 自定义SQL**。每选一项追加一个该类规则块。

规则块字段（以完整性为例，逐字 label）：

- `规则类型`：`字段级` / `表级`（这是**生效范围/级别**，字段名叫「规则类型」，不叫「生效范围」；准确性块无此字段，恒字段级）
- `字段`：下拉，选项为该表真实列名
- `统计函数`：下拉，随大规则/规则类型变化（见下）
- `过滤条件`（旁有「全局参数」链接）
- `校验方法`：`固定值`（…）
- `期望值`：**比较符下拉（`<` `>` `=` 等）+ 数值输入**，如「< 1」「= 0」「> 5」
- `强弱规则`：`弱规则` / `强规则`
- `规则描述`：文本
- 块操作：克隆；编辑态有 保存 / 取消。

已确认的「统计函数」清单：

| 大规则 | 规则类型 | 统计函数（逐字） |
| ---- | ---- | ---- |
| 完整性校验 | 字段级 | 空值数 / 空值率 / 空串数 / 空串率 |
| 准确性校验 | （恒字段级） | 求和 / 求平均 / 负值比 / 零值比 / 正值比（**无最大值/最小值**） |
| 规范性校验 | （恒字段级，含格式类） | 数值-取值范围 / 数值-枚举范围 / 数值-枚举个数 / 格式-身份证号 / 格式-手机号 / 格式-邮箱 / 字符串-最大长度 / 字符串-最小长度（**带前缀；无「数据精度」、无「空值数/重复数」**） |
| 唯一性校验 | （恒字段级） | 重复数 / 重复率 / 非重复个数 / 非重复占比（无前缀） |
| 完整性校验 | 表级 | 表行数（切表级后统计函数仅表行数） |

> 准确性/规范性/唯一性块**无「规则类型」字段**（恒字段级）；仅完整性有「规则类型=字段级/表级」。规范性的格式类（身份证/手机/邮箱）也在「统计函数」下拉里，文案带「格式-」前缀，不是独立的生效范围。

规则详情抽屉（点表名打开）：tab `规则管理` / `远程触发`；基本信息（规则名称[编辑] / 执行周期 / 告警方式 / 执行时间 / 接收人 / 规则拼接包 / 规则SQL[查看]）；底部按钮 **关闭检测 / 立即执行 / 编辑调度属性**。

**执行规则用「立即执行」**（不是「立即运行」）。

## 多表比对规则向导 `#/dq/rule/dataCheck/add`

步骤：**① 选择左侧表 → ② 选择右侧表 → ③ 选择字段 → ④ 执行配置**。术语是 **左侧表 / 右侧表**（不是「主表/比对表/关联字段/比对字段」）。

- ① 选择左侧表：`规则名称` / `选择数据源`（旁「添加数据源」链接）/ `选择左侧表` + 数据预览。② 选择右侧表同构。
- ③ 选择字段：左右两栏字段映射（左侧表字段/类型 ↔ 右侧表字段/类型，连线），右侧「同行映射」「同名映射」按钮 + 加主键；下方匹配条件复选（默认仅精确相等，勾选某条件即对该维度放宽容差，计为「成功匹配」）：
  - 记录数差异：对比左右表总记录数，差距小于等于 N% 时计为成功匹配
  - 数值差异百分比：对比数值型数据时，差距百分比小于等于 N%（源码 `R<=L*(1+N/100)` 计为匹配）
  - 数值差异绝对值：差距绝对值小于等于 N（源码 `abs(L-R)<=N`）
  - 数值对比忽略小数点，忽略小数点后 N 位（**SR3 实现为 `cast(列 AS DECIMAL(38,10))`、非 round 到 N 位，见 `StarRocks3SqlOperator` 注释「SR3 不支持 round」；与「忽略小数点后 N 位」字面语义可能不符，写该条件用例前必 live 确认实际行为**）
  - 字符不区分大小写（源码 `lower(L)=lower(R)`）
  - 空值与 NULL 等价（源码：一侧 NULL、另一侧空串 `length=0` 视为相等）
  - 是否强规则：复选项 UI 存在（文案「强规则校验未通过或运行失败时，会影响关联任务的运行状态」），但**多表比对无实际强弱规则配置语义，不作测试点**（用户确认 2026-06-25）
  - 匹配条件 SQL 模板出处：`dt-center-assets/service/.../valid/sql/core/VerifySqlOperator.java`；SR3 比对 where 构造在 `StarRocks3SqlOperator.getWhereSqlBySetting`
- ④ 执行配置：调度。
- 监控报告（任务查询点表名打开）：顶部「差异总数 / 差异比例」；表名 / 分区名 / 数据源名称 / 总记录数（左右各一列）；「异常数据」分五个分类 tab（各带计数，可下载明细 `pw_test.dq_*`）：
  - 逻辑主键匹配，但数据不匹配（主键命中但映射字段值不一致）
  - 左表数据在右表未找到
  - 右表数据在左表未找到
  - 左表逻辑主键为空
  - 右表逻辑主键为空
  - 明细列形如 `L_<字段>` / `R_<字段>`（如 L_order_id、L_trade_amount、R_order_id、R_trade_amount）。
  - 构造「左/右表逻辑主键为空」样本：建表用独立存储主键（如 `id`）作 `DUPLICATE KEY` / 分桶键，逻辑主键列（如 order_id）设为可空普通列并插 NULL 行，避免分桶键为 NULL 的建表风险。

## 任务查询 `#/dq/taskQuery`

筛选：表名/任务名称搜索、计划时间、最近修改人、我收藏的表。列：表 | 任务名称 | 状态 | 类型 | 数据源 | 执行周期 | 是否关联任务 | 计划时间…。

**状态值：`校验通过` / `校验异常`**（失败/规则不通过/运行异常均归「校验异常」；概览运维指标桶为 校验通过/校验异常/其他）。**未观察到独立的「校验未通过」态**——历史用例里写的「校验未通过」需改为「校验异常」（执行时以页面实际态为准）。

## 实时校验 `#/dq/realTimeVerification`

基于 **Kafka Topic** 的流式抽检。列：Topic | 规则名称 | 最近运行状态 | 时间间隔 | 样本量上限(条) | 最近抽检时间 | 今日告警次数 | 操作。右上「新建规则」。

**面向流式 Topic，不适用 StarRocks 批量表**——SR3.x 适配用例不覆盖实时校验。

## 脏数据管理 `#/dq/project/dirtyDataManage`
