# 【151624】验证JSON 格式校验管理导入顶层同名 key 时不再误判为已存在子层级

## 前置条件

```
1. 已部署 customltem/dt-center-assets 修复分支 hotfix_6.3.x_ltqc_151624 的包。
2. 使用测试环境登录 DataAssets，租户为 pw_test，数据质量项目为 pw_test，当前账号有【数据质量 → 通用配置 → json格式校验管理】查看、导入、删除、展开层级的权限。
3. 本缺陷可完全通过 UI 导入构造，不依赖业务源表 SQL；导入时数据源类型选择 SparkThrift2.x。
4. 若页面中已存在以下测试 key，先在 json格式校验管理中搜索并删除，确保本次导入从干净状态开始：
   - hotfix151624Root
   - sameKey151624
5. 准备两个符合 json_format_import_template.xlsx 格式的导入文件，两个文件都必须保留一层、二层、三层、四层、五层共 5 个 Sheet，三层到五层只保留表头即可。

第一次导入文件：

一层 Sheet（表头：* key | 中文名称 | value格式）
| hotfix151624Root | hotfix151624根节点 | |

二层 Sheet（表头：* 第一层级key名 | * key | 中文名称 | value格式）
| hotfix151624Root | sameKey151624 | 子层级同名key | ^[0-9]+$ |

第二次导入文件：

一层 Sheet（表头：* key | 中文名称 | value格式）
| sameKey151624 | 顶层同名key | ^[A-Z]+$ |

二层、三层、四层、五层 Sheet：仅保留表头，不写数据。
```

## 用例步骤

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 进入【数据质量 → 通用配置 → json格式校验管理】，数据源类型选择 SparkThrift2.x，分别搜索 `hotfix151624Root`、`sameKey151624` | 页面正常加载；若存在历史测试数据，完成删除后再次搜索不再显示对应记录 |
| 2 | 点击【导入】按钮，在导入弹窗中保持重复处理规则为默认「重复则跳过」，上传第一次导入文件并点击【确定】 | 导入成功；列表刷新后显示顶层 key `hotfix151624Root` |
| 3 | 展开 `hotfix151624Root` | 子层级显示 `sameKey151624`，中文名称为「子层级同名key」，value格式为 `^[0-9]+$` |
| 4 | 再次点击【导入】按钮，保持重复处理规则为「重复则跳过」，上传第二次导入文件并点击【确定】 | 页面提示导入成功；本次导入不会因为二层已存在 `sameKey151624` 而把顶层 `sameKey151624` 误判为重复 |
| 5 | 在列表中搜索 `sameKey151624`，不展开任何父节点，查看顶层搜索结果 | 顶层列表显示 `sameKey151624`，中文名称为「顶层同名key」，value格式为 `^[A-Z]+$`；该记录与 `hotfix151624Root` 下的子层级同名 key 同时存在 |
| 6 | 清空搜索条件，展开 `hotfix151624Root`，再次核对其子层级 `sameKey151624` | 子层级记录仍保留在 `hotfix151624Root` 下，value格式仍为 `^[0-9]+$`，未被第二次顶层导入覆盖或移动 |
| 7 | 进入【数据质量 → 规则集管理】新增或编辑任意测试规则集，在字段级规则中打开「格式-json格式校验」的校验 key 选择控件，分别搜索顶层 `sameKey151624` 和 `hotfix151624Root.sameKey151624` | 两条同名不同层级的 key 均可被识别；顶层 key 不再缺失，子层级 key 不被错误指向或替换 |
| 8 | 返回【json格式校验管理】，分别删除顶层 `sameKey151624` 和 `hotfix151624Root` | 测试数据清理成功；删除顶层同名 key 不影响已经展开定位到的父子层级删除流程 |
