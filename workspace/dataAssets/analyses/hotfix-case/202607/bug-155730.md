# 【155730】验证【数据质量】对表对比下载异常数据下载失败

## 前置条件

- 环境：测试环境。
- 产品：线上问题统计。
- 引擎：`DTHadoop_DTHadoop 3.2.1`。
- 客户场景：标准版本_合肥晶合集成。
- 准备可执行的 Doris 数据源，并确认 Doris 集群允许的副本数范围包含测试配置值（例如 `3`）。
- 在数据质量模块配置一个 Doris 对表对比任务，配置规则集和多表比对，使任务能够生成异常数据。
- 将 Doris 副本数配置为 `3`（或其他大于等于 3 的合法值），并保留异常数据下载入口。

## 用例步骤

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 在数据质量模块进入 Doris 对表对比配置，设置合法的 Doris 副本数（例如 `3`），保存规则集和多表比对配置。 | 配置保存成功，副本数为 `3`，没有被页面或接口重置为 `1`。 |
| 2 | 执行该对表对比任务，制造或保留至少一条异常数据，使系统进入异常数据下载流程。 | 任务执行成功并生成异常数据记录，不因 CTAS 副本数非法而失败。 |
| 3 | 查看任务执行日志或生成 SQL，检查异常数据表、规则集临时表和多表比对临时表的 `PROPERTIES("replication_num" = "...")`。 | 所有相关建表 SQL 均使用配置的合法副本数（例如 `3`），不得出现写死的 `replication_num = "1"`。 |
| 4 | 点击下载异常数据，或调用产品提供的异常数据下载入口。 | 下载成功，返回异常数据文件或结果集，不再出现 `Replication num should between 3 and 32767`。 |
| 5 | 将副本数改为另一合法值并重复执行一次，检查规则集和多表比对两条路径。 | 两条路径均跟随新配置值生成 SQL，证明不存在只修复单一路径的写死值。 |
