## 背景、目标与成功标准

本基线用于泸州老窖 v7.0.0 数据资产定制化代码剥离后的回归。目标是把蓝湖需求、产品说明书、禅道历史用例和 release 源码中的有效行为整理成可读、可追踪、可自动化扩展的测试资产。成功标准：24 个子需求均有功能方向覆盖；每条用例可追溯到 TP、PRD 稳定 ID 和需求 ID；YAML 能独立构建 XMind；关键异常、边界、权限和数据完整性均有明确预期。

父需求 15911 只表示本聚合范围；它本身不作为测试场景，代码剥离方案文档交付也不生成执行用例。

## 角色、权限与前置条件

账号只使用 `UserA` 和 `UserB`。`UserA` 是管理员主流程账号，具备当前用例所需的页面、操作、导入和导出权限，并属于可执行目录行拖拽的管理员身份之一。`UserB` 是权限验证账号；每条权限用例必须在前置条件中写明 UserB 已授予和未授予的具体权限、是否属于目标用户组及该账号在本用例中的用途，不记录真实账号或凭据。

通用前置：泸州老窖定制应用已部署，租户与两个抽象账号可用；各用例分别写明所需 L1～L5、标准、码表、组织架构和审计记录。数据权限和码表引用场景使用一个数据源占位符 ${DataSourceA}，SQL 按 SparkThrift2.x 执行。

## 状态与数据规则

目录新建默认为草稿，已发布目录才能关联 L4 数据表或标准；发布/下线必须填写备注并记录审计。L4/L5 导入只维护元数据同步产生的业务属性，不创建表或字段。

数据表批量删除仅对草稿与已下线表生效，选中含已发布表时已发布表静默剔除、无阻断提示；全选已发布时删除入口禁用；部分失败仅日志、接口返回成功、无明细反馈。

码表手工导入按代码精确匹配更新，空编码新增，找不到匹配关系报错；引用数据表时从当前源表实时读取，配置方式决定可用操作，手工导入不得覆盖引用源数据。码表内容发生变化生成版本并支持任意两版本比对；引用数据表模式下源表数据内容变化不触发版本，详情仅展示源表前 1000 条。

安全与隐私字段按字段级别计算，表级展示取字段中的最高等级。行权限同一策略内按且/或计算，多个策略按外层或汇总；用户与用户组在同一策略中互斥。权限策略编辑、禁用、删除、回收、失效和移除单个生效对象后，数据预览、详情和接口查询结果必须实时遵循最新状态；数据导出不应用行权限。

## 异常、边界与兼容性

覆盖编码存在未删除数据时重置阻断、删除后重置物理清理、编码溢出和租户隔离；目录/标准/码表/L4/L5 导入的必填、重复、枚举、层级、字符长度、错误文件和已发布状态；列表配置最小/最大数量、级联清空、无结果和批量部分失败；L4/L5 异步分批导出与 799、800、801 分批边界（<800 单批、≥800 按 800 拆批）。目录 L1、L2、L3 各准备 120 条数据，在每页 100 条条件下进入第 2 页，分别拖动第 101/102 条和第 119/120 条并刷新验证持久化；同时保留小数据量拖拽。

覆盖引用数据表源不可用、字段不存在、空值、重复值、切换清理、超过 1000 行仅展示前 1000 行；覆盖行权限 0/1/5/6 条件（上限为前端约束、后端不强制）、五种操作符、且/或、行列组合、用户/用户组互斥、全行覆盖、过期和回收。

兼容性边界：不固化真实环境 URL、Cookie、账号、数据库名或表名；用例中的数据源只写 ${DataSourceA}，实际 SQL 使用 SparkThrift2.x。

## 验收标准

AC-001～AC-024 分别对应 24 个子需求的可执行回归集合。所有 P0 场景必须覆盖主链路和阻断性异常；P1 覆盖关键组合和生命周期；P2 覆盖展示、排序、分页与边界。纯接口执行不进入本功能用例集。

交付验收还包括：PRD 使用稳定 FR/BR/ER/AC/PD ID；test-points.md 的每个 TP 引用稳定 ID且摘要链有效；YAML 的每条用例有 requirement_id、priority、步骤、预期、前置条件和 TP source_ref，XMind 不生成未分类占位标签；XMind 每个 L1 标签包含需求 ID，前置条件位于标题节点 notes，功能用例直接挂在需求 L1 下；纯接口执行用例不进入功能用例集；所有静态 lint、构建和导出一致性校验通过。
