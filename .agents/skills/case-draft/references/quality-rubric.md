# Case Draft 质量标准

## 必须满足

- 每条用例只有一个清楚目标，标题能说明条件和结果。
- 前置条件只写本用例真正需要的状态、权限和数据。
- 步骤可执行，顺序明确，不把多个独立场景塞进一条用例。
- 预期结果可以观察或核对，避免“正常”“正确”“符合预期”等空泛表达。
- 主路径、高风险异常、边界、权限、数据一致性和重要回归点都有对应覆盖。
- 页面文案未校准时明确标记，不写成已经从环境确认。
- 优先级来自影响和回归价值，不按比例分配。

## 建议满足

- 相同前置和步骤不大段复制，可用共享说明或参数化表格。
- 组合过多时使用等价类、边界值或成对组合，并说明取舍。
- 用例正文面向测试人员阅读；哈希、内部映射和来源 ID 留在 `.process/`。
- 中文使用短句。一个步骤只描述一个动作，避免中英术语连续堆叠。

## 评审问题

内容评审只回答以下问题：

1. 是否遗漏会改变用户结果的主要场景？
2. 是否存在无法执行、无法观察或互相矛盾的步骤？
3. 是否把未知内容写成了确定内容？
4. 是否有重复用例可以合并？
5. 优先级是否与风险一致？

字段、计数、链接、frontmatter 和 XMind 一致性由命令检查，不重复进行语言模型评审。
