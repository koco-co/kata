# 知识规则

查询或更新项目业务知识时，参照本文。

项目知识落到 `workspace/{project}/knowledge/**`；项目规则落到 `workspace/{project}/rules/**`——后者承载该项目的编写与格式约束。业务事实与实现说明须分仓保存；仅当用户明确要求时，方可将实现上下文沉淀为业务知识。

低置信度的更新写入之前，须先确认。除非用户明确指定了目标项目，否则不得跨项目边界写入。条目优先求简洁、求有来源支撑——清楚标注所保留的模块、术语、规则、踩坑或工作流。

查询时，报告命中的知识条目及其 SourceRef ID。无可靠条目命中时，明确声明知识库中无已确认匹配，不得凭空捏造。
