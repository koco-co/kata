# Playwright 环境策略

## 何时需要环境

- `review`：不需要。
- `generate`：已有页面资料时不需要；没有页面资料仍可生成骨架，但必须标为 `generated-not-run`。
- `run` / `repair`：必须指定环境并通过预检。

## 选择环境

按顺序使用：

1. 用户明确给出的环境。
2. feature manifest 记录且仍有效的环境。
3. 项目配置中唯一默认环境。
4. 存在多个候选时，列出名称和用途，请用户选择。

不得在 Skill 中写个人环境默认值。

## 预检

```bash
kata env show <env>
kata env doctor <env>
```

预检至少确认：配置权限、会话可用、租户匹配、项目与数据源唯一匹配、浏览器依赖、目标写入权限和 `allow_write` 意图。

## 传递秘密

- 环境命令不得继承父进程全部变量。
- Cookie 不写日志、Allure 参数、截图文件名或错误正文。
- 子命令需要额外变量时按名称显式继承。
- HTTP 环境给出明确警告；共享或生产环境要求 HTTPS。

## 共享环境

- 每次运行生成唯一前缀。
- 创建的业务记录写入 manifest 或 run record。
- 清理只按明确 ID/名称执行。
- 权限不足、租户不符或所有权不清楚时停止写入，不尝试扩大权限或范围。
