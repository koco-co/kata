# Playwright 脚本规范

## 测试结构

- 一条测试聚焦一个可独立判断的业务场景；共享登录、导航和数据准备放入 fixture/helper。
- 页面对象只封装稳定的页面行为，不把断言和业务分支全部藏进工具函数。
- 测试数据名称包含运行 ID 或唯一前缀，并记录在 manifest 中。
- 时间、随机数和业务日期由 fixture 注入，避免脚本各处直接调用当前时间。

## 定位与等待

优先级：

1. `getByRole` + 可访问名称
2. `getByLabel`
3. `getByTestId`
4. 稳定业务属性
5. CSS/XPath（最后选择，并说明原因）

- 禁止用 `waitForTimeout` 解决同步问题。
- 使用 Playwright 自动等待断言，例如 `toBeVisible`、`toHaveText`、`toHaveURL`。
- 列表中存在同名元素时，用稳定容器、业务 ID 或可见关系消歧，不用随 DOM 顺序变化的 `nth()` 作为默认方案。

## 动作与断言

- 核心业务动作通过 UI 完成。
- 每个关键动作后断言用户可见结果或最终业务记录；不要只断言按钮存在。
- 不降低断言范围换取通过。不吞异常，不在失败后继续伪造成功摘要。
- `test.skip` 只用于 manifest 明确排除且有原因的场景，不在运行中临时跳过失败用例。

## API、数据库与清理

- API/DB 仅用于项目策略允许的准备、清理或诊断；调用写入 `run.json`。
- 不用 API 完成用户要求验证的核心页面动作。
- 清理只使用本次运行记录的 ID/名称。找不到明确所有权时保留数据并报告，不扩大删除范围。

## 失败产物

失败至少保留：

- 错误摘要与完整日志路径
- 截图
- trace（环境允许时）
- 目标 URL 与关键定位信息（脱敏）
- 测试数据 ID/名称

视频和网络日志按项目需要开启，不默认永久保存。

## 可由 lint 检查的规则

建议增加静态检查：

- 禁止 `waitForTimeout`。
- 禁止空 `catch` 和无重新抛出的宽泛 `catch`。
- 禁止在测试中硬编码 Cookie、密码、租户和生产 URL。
- 禁止未记录的全局数据清理。
- runner 的导入项必须存在于 manifest。
