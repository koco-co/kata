# Handoff

Each completed self-run produces a double-track handoff:

1. **handoff.json** (`features/<featureId>/results/<run-id>/handoff.json`) — strict `PlaywrightAutomationHandoff@2` JSON. Written by self-run step.
2. **handoff.md** — rendered from json by `kata handoff render <featureId> --run <run-id>`. Header `<!-- generated by kata handoff render; do not edit -->`. Never hand-edit.

Quality gate `handoff_double_track` enforces both files exist and md has the generated header.

## User-facing completion text

The final handoff message must include the human acceptance command from `self-run.md`, even when the run is passed, blocked, failed, or partial. Do not rely on `handoff.md` or `handoff.json` existing as a substitute for printing the command in chat.

The command must be a headful full runner command, not a smoke or single-case command:

```bash
KATA_DATAASSETS_ENV=<env> KATA_ACTIVE_PROJECT=<project> npx playwright test 'features/<featureId>/tests/runners/full.spec.ts' --project=chromium --headed --reporter=line
```

If the actual self-run used a headless command, keep that evidence in `run_command`, but still print this `--headed` full test command for human acceptance. Never declare E2E completion without this command in the final user-facing text.

Schema reference: `.ai/core/schemas/PlaywrightAutomationHandoff.v2.schema.json`.
