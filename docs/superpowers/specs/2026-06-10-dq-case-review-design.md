## 4. 执行方案（方案 A：subagent-driven 分批）

按依赖关系切 3 批顺序推进；每批走「源码 reader 建基线 → implementer 改写 → spec review → quality review → 落盘」，符合项目 `subagent-driven-development` 规范。

- **批次 1（地基）**：规则集&规则任务&校验结果查询 47 例
  - 确立共享测试表 + 共享规则集设计 + golden 重构模式（前置「已存在规则集」+ 步骤加规则包）
  - 是后续批次复用的基础，必须先做
- **批次 2（复用批次 1 数据）**：数据质量报告 15 + 通用配置 10
  - 前置直接引用批次 1 产出的规则任务名 / 校验实例 / 结果数据，不另造测试数据
  - 报告关联维表设置直接引用已有数据作步骤
- **批次 3（独立）**：规则库配置 10 + 总览 6 + 项目管理 6
  - 对照源码校正字段 / 统计口径 / 权限；总览统计类预期需与规则任务产生的数据联动一致

依赖顺序（批次 1 先定共享夹具，批次 2 才能复用）天然排斥并行，故不采用 Workflow 大规模并行。

## 5. 单条用例审查标准（7 维）

对齐 `.claude/prompt/_shared/case-qa.md`、`output-artifacts.md`、`case-format-sample.md` 的当前 runtime 版本，逐字匹配源码证据：

1. **标题三段式**：`【Pn】+ 验证动词 + 验证对象【业务括号】+ 场景`；业务括号原样保留，不按通用规则移除。
2. **前置条件**：写成可执行 / 可准备 / 可核对的测试数据或环境状态（SQL 注释块顶部 `/* */` 说明环境+目的，可执行 SQL，`SELECT` 末尾 `-- 预期结果：N`）；占位符用 `${SchemaA}` / `${table_name}`，不硬编码租户库名。跨用例基础依赖（数据源 / 库 / 维表 / 权限）留前置；业务准备链路（新增报告、执行规则任务、准备明细等）下沉到步骤第 1 步并在预期写明准备结果。不得用 `SELECT 1` / 泛泛「页面已存在数据」/ 只有「已登录」占位，也不得用「数据均在步骤中准备」这类元说明占位。
3. **步骤 = 单页面动作**：监控规则 / 调度属性等不同页面动作拆成不同行；按钮 / Tab / 字段 / 枚举逐字匹配源码文案（不归一 `sql→SQL`、不把「字段」写成「字段级」、不用动作泛称替按钮全称）。
4. **预期**：`1) 2)` 编号断言；保存类操作需验证保存 + 回显。
5. **优先级 marker** 与 XMind 镜像一致。
6. **SourceRef** 只存结构化数据层，不泄漏进 archive / xmind 展示正文。
7. **规则描述等必填字段** 不得省略，预期需覆盖保存 + 回显。

## 7. 分类调整规则（差异化，不一刀切）

- **golden 规则任务类（47，逐条甄别）**
  - 默认：前置 → 「已存在规则集（关联表: `${table_name}`）」+ 表数据准备；步骤 → 在该规则集点「新增」加规则包 → 配置子规则 → 新建规则任务引入该子规则 → 执行 → 校验结果查询。
  - **例外保留完整准备**（不可一句话带过）：多表数据/内容对比、自定义 SQL 各类、时效性（周期性/及时性，时间窗数据）、合理性-数据变化趋势（多分区单调序列）等——需保留完整建表 + 数据 + 多分区/多表准备。
  - 超时处理、查看日志 2 条（非 golden）按源码实际行为校正。
- **数据质量报告（15）/ 通用配置（10）**：前置直接复用批次 1 产出的规则任务名 / 校验实例 / 结果数据，不另造测试数据；报告关联维表设置直接引用已有数据作步骤。
- **规则库配置（10）/ 总览（6）/ 项目管理（6）**：对照源码校正字段 / 统计口径 / 权限；总览统计类预期需与规则任务产生的数据联动一致。
- **去重 / 合并 / 补漏**：删除重复测试点、合并冗余用例；按源码功能补明显未覆盖的核心点。重大增删先在变更摘要列清单给用户点头，小修小补直接做并留痕。

## 8. 产物与一致性校验

- **编辑面 = `archive.md`**（markdown，易改、git-diff 可读）。implementer 只改 DQ 相关章节；archive 的 DQ 段补成 `### 模块 / #### 子模块 / ##### 用例` 三层结构镜像 XMind，保证往返保真。
- **`cases.xmind` 同步**：每批末把 archive 改动同步进 xmind，**优先在现有 xmind 上定点打补丁**（只改动到的 topic 的 title / marker / notes / 步骤），保留未改用例的 id / 折叠 / labels，避免整树重生丢结构。
- **变更摘要 `dq-review-change-summary.md`**：逐例记「改了什么 + 为什么 + 源码依据（commit）」，外加「重大增删待用户点头」清单。
- **一致性自检（每批 gate）**：复用审计脚本，archive↔xmind 6 维逐字校验（用例数 / 优先级 marker / 标题 / 前置 / 步骤 / 预期）；任一不一致先回滚该批，不带病落盘。frontmatter `case_count` 同步更新。
