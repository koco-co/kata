# diff-scan

## 功能说明

扫描源代码 diff，只报告可复现、有证据支撑的缺陷。是代码变更后的静态分析工具，专注于从 diff 中发现逻辑错误、边界问题、空指针、类型错误等可复现的 bug。

## 输入

- **diff** (required): 代码变更，可以是：
  - git diff 输出
  - git branch 对
  - 变更文件列表
  - PR diff（GitHub URL）
- **project** (optional): workspace ID。

**示例**:
```
"扫描这个分支的 diff"
"检查 main..feature 之间的变更"
"分析当前 PR 的代码变更"
```

## 输出

- **findings**: 发现的可复现缺陷列表。
- **report**: 综合扫描报告。

## 执行流程

1. **获取 diff**：从用户输入获取 diff 内容或路径。
2. **遍历变更**：逐文件检查变更内容。
3. **代码分析**：对每个变更段分析：
   - 变更的类型（新增/修改/删除）
   - 变更的上下文（周边代码）
   - 潜在的逻辑问题
4. **缺陷确认**：只记录能依据 diff 与周边代码复现的 bug。
5. **报告输出**：生成扫描报告，列出所有缺陷及其证据。

## 产物要求

### 报告结构

每个发现必须包含：
| 字段 | 说明 |
|------|------|
| 文件 | 缺陷所在的文件路径 |
| 行号 | 缺陷的具体行号 |
| 缺陷类型 | 逻辑错误/空指针/类型错误/边界问题等 |
| 复现依据 | 依据的代码内容和上下文 |
| 影响评估 | 对功能的潜在影响 |
| 修复建议 | 推荐的修复方式 |

### 证据纪律

- **仅报告能依据所给 diff 与周边代码复现的 bug**。
- 无证据支撑的风险点不得作为缺陷报告，应标记为建议而非缺陷。
- 需要 `repo.diff@1` 作为 SourceRef。
- `unreproducible_risk` 应在缺陷列表中省略。

### 安全约束

- 源仓库（`workspace/{project}/.kata/repos/**`）只读，不进行任何修改。
- 分析结果只输出报告，不能执行代码变更。
